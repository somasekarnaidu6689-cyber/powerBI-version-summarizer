# Power BI Diff Tool

## Overview

This repository contains a Power BI comparison tool for PBIP folder-based projects. The current main flow is built for PR validation and prints a console-only summary of differences between two PBIP versions.

- Supported input: PBIP folder projects containing a `.pbip` marker file.
- The main CLI uses `--old` and `--new` paths.
- No HTML, PDF, or Excel output is generated by the current default workflow.

## What this tool does

The tool compares two Power BI PBIP projects and reports differences across:

- Semantic model definitions in `SemanticModel`
- Report definitions in `Report/definition`
- Report layout details in `report.json`

## Architecture and key modules

### `pbix_diff/run.py`

The main orchestrator:

- parses `--old` and `--new`
- detects supported input formats with `detector.py`
- extracts PBIP contents with `extractor.py`
- compares semantic models, report definitions, and layout
- prints a console summary using `reporter.py`

The current workflow requires both `--old` and `--new` to be PBIP folders.

### `pbix_diff/detector.py`

Detects input formats:

- `.pbix` → binary ZIP archive
- PBIP folder with `*.pbip` marker → PBIP project
- `.bim` → data model JSON
- `.json` / `.pbir` → report JSON

The PR validation path restricts execution to PBIP folders only.

### `pbix_diff/extractor.py`

Extracts paths from supported inputs.

- PBIP projects → locates `SemanticModel` and `Report` folders
- `.pbix` archives → extracts contents to `/tmp`
- JSON artifacts → passed through directly

### `pbix_diff/comparators/model.py`

Compares semantic model TMDL definitions.

It reports:

- tables added / removed
- columns added / removed / modified
- measures added / removed / modified
- partition/source changes
- relationship changes
- role permission changes
- model metadata changes

### `pbix_diff/comparators/report.py`

Compares report page definitions.

It identifies:

- pages added
- pages removed
- pages changed
- visual differences inside existing pages
- filter differences
- page setting differences

Note: the current return structure includes `pages_changed`, while `visuals_modified` and `filters_changed` remain legacy placeholders.

### `pbix_diff/comparators/layout.py`

Compares report layout from `report.json`.

It detects:

- canvas/page setting changes
- bookmark changes
- z-order changes

### `pbix_diff/large_file_handler.py`

Loads large JSON safely:

- streams files over `LARGE_FILE_THRESHOLD_MB`
- loads smaller files normally
- warns about small files on Databricks when configured

### `pbix_diff/reporter.py`

Prints the final summary to the console.

### `pbix_diff/ai_summarizer.py`

Provides optional AI summary generation using Groq, but this module is not currently invoked by `pbix_diff/run.py`.

## Configuration

The repository loads environment values from `.env` via `pbix_diff/config.py`.

Current config values:

- `OLD_PATH` — optional path placeholder; current CLI still requires `--old`
- `NEW_PATH` — optional path placeholder; current CLI still requires `--new`
- `ENVIRONMENT` — runtime environment (`local`, `rdp`, `databricks`)
- `LARGE_FILE_THRESHOLD_MB` — file size threshold for JSON streaming
- `INCLUDE_LAYOUT_DIFF` — whether layout diffing runs
- `DBX_WARN_SMALL_FILES` — Databricks small-file warning
- `DBX_LOG_DURATION` — Databricks duration logging
- `SAMPLE_PAGES` — optional page sampling value

Optional AI-related keys exist in `.env.example` but are not currently wired into the main run path:

- `ENABLE_AI_SUMMARY`
- `GROQ_API_KEY`

## How to run

1. Open a terminal in the repository root:

```powershell
cd C:\Users\somsekar.naidu\Desktop\projects
```

2. Install dependencies:

```powershell
python -m pip install -r pbix_diff/requirements.txt
```

3. Copy `.env.example` to `.env`:

```powershell
copy .env.example .env
```

4. Run the comparison tool:

```powershell
python .\pbix_diff\run.py --old "powerBi/v1" --new "powerBi/v2"
```

## Output

- The tool prints a console summary only.
- No HTML report generation is used in the current workflow.

## GitHub PR Validation

A PR validation workflow exists in `.github/workflows/pr-validation.yml`.

It:

- triggers on pull request events
- detects changed PBIP project folders
- extracts the old version from the base branch
- compares the old and new PBIP project versions
- runs unit tests
- posts or updates a PR comment with results

## Notes

- The current PR path enforces PBIP folders only.
- AI summarization code is present, but not used by the main CLI today.
- `pbix_diff/exporter.py` is legacy and is not part of the default PR validation flow.

## Troubleshooting

- If layout diffing is too slow, set `INCLUDE_LAYOUT_DIFF=False` in `.env`.
- If `.env` settings are not needed, use CLI `--old` and `--new` explicitly.
- If you do not want AI summaries, leave `ENABLE_AI_SUMMARY=False`.
